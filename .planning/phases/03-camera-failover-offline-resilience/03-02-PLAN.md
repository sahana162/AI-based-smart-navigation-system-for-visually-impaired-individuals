# Plan 3.2: Camera Failover, Mid-Inference Hardening & Hot-Swap Obstacle Resume

<objective>
Harden the camera failover and recovery lifecycle: protect `UvcCameraService.captureFrame()` against abrupt physical USB disconnects mid-inference, eliminate phone camera controller memory leaks, and guarantee that live 2 fps obstacle monitoring automatically restarts when the smart glasses are plugged back in.

Purpose: Prevent unhandled crashes or frozen video loops when USB cables wiggle, and ensure hands-free obstacle protection never stops working after hot-plugging.
Output: Resilient UVC capture logic, clean camera controller lifecycle management, and automatic obstacle scanning resumption on hot-swap.
</objective>

<task type="auto">
  <name>Harden UvcCameraService Against Mid-Inference Disconnects</name>
  <files>lib/core/services/uvc_camera_service.dart</files>
  <action>
    In `lib/core/services/uvc_camera_service.dart`:
    1. In `captureFrame()`:
       - Wrap calls to `_controller!.takePicture()` in defensive try/catch blocks specifically catching `PlatformException`, `CameraException`, and generic `Exception`.
       - If a `PlatformException` or communication error occurs (indicating the USB device handle was severed):
         a. Log warning: `[UvcCameraService] USB device communication severed during frame capture: $e`.
         b. Cancel `_streamTimer` and call `stopStreaming()`.
         c. Clean up controller via `_cleanupController()`.
         d. Set `_connectionState = UvcConnectionState.disconnected`.
         e. Clear `_latestFrameBytes` and notify listeners immediately.
       - Ensure `_isCapturing` flag is reset to `false` in the `finally` block under all error conditions.
    2. In `startStreaming()`:
       - Ensure that if `_controller` becomes null or is closed while the timer is firing, `stopStreaming()` is called immediately without throwing unhandled null assertion errors.
    AVOID: Leaving `_isCapturing = true` after a failed capture call.
  </action>
  <verify>flutter analyze lib/core/services/uvc_camera_service.dart</verify>
  <done>UvcCameraService gracefully handles physical USB disconnection mid-capture without crashing or deadlocking.</done>
</task>

<task type="auto">
  <name>Auto-Restore Obstacle Monitoring and Prevent Leaks in NavigationScreen</name>
  <files>lib/ui/screens/navigation_screen.dart</files>
  <action>
    In `lib/ui/screens/navigation_screen.dart`:
    1. In `_initUvcPipeline()`:
       - When the UVC camera successfully connects (`connected == true`):
         Check `widget.storageService.obstacleAlertsDefaultEnabled`. If true, automatically invoke `_startLiveObstacleMonitoring()`.
    2. In `_switchCameraSource(bool toPhone)`:
       - When switching to glasses (`toPhone == false`):
         a. If `_phoneCameraController` is active or streaming, await `_phoneCameraController!.stopImageStream()` safely in a try/catch.
         b. Await `_phoneCameraController!.dispose()`.
         c. Set `_phoneCameraController = null`.
         d. In `_initUvcPipeline()`, auto-start `_startLiveObstacleMonitoring()` once connected so the 2 fps glasses stream resumes continuous detection.
       - When switching to phone (`toPhone == true`):
         a. Stop UVC stream via `_uvcService.stopStreaming()`.
         b. Initialize phone camera and start `_phoneCameraController!.startImageStream(_handleCameraFrame)` as before.
    3. In `_handleUvcFrame(Uint8List frameBytes)`:
       - Guard against empty or truncated frames (`frameBytes.length < 1000`) before running inference.
    AVOID: Leaking CameraController instances or failing to restart obstacle detection after re-plugging glasses.
  </action>
  <verify>flutter analyze lib/ui/screens/navigation_screen.dart</verify>
  <done>NavigationScreen seamlessly switches between glasses and phone camera, eliminates memory leaks, and auto-resumes obstacle monitoring.</done>
